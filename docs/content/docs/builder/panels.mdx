علاوه بر ساخت ربات، ربات‌ساز می‌تواند **پنل** هم بفروشد. «پنل» یعنی یک **حساب ادمین روی پنل پاسارگارد خودِ شما** با حجم و مدت مشخص. مشتری پنل را می‌خرد؛ ربات‌ساز **خودکار**:

1. روی پنل اصلی شما یک **ادمین** با نام کاربری و رمز قوی می‌سازد (با حجم پلن)،
2. **ربات مشتری** را با همان ادمین به پنل وصل می‌کند (بدون اینکه مشتری چیزی تایپ کند)،
3. اطلاعات ورود را برای مشتری می‌فرستد.

پس مشتری فقط تعرفه را انتخاب و پرداخت می‌کند و ربات فروشش روی پنل شما آماده فروش می‌شود.

<Callout type="info" title="چه چیزی خودکار است؟">
ساخت ادمین، تنظیم حجم و سقف کاربر، اتصال ربات، هشدار مصرف، غیرفعال‌سازی هنگام اتمام حجم یا مدت، و فعال‌سازی دوباره بعد از تمدید یا خرید حجم اضافه. شما فقط تعرفه‌ها و تأیید رسیدها (کارت‌به‌کارت) را مدیریت می‌کنید.
</Callout>

## راه‌اندازی

از **⚙️ پنل مدیریت ← 🧩 فروش پنل** شروع کنید.

<Steps>
<Step>

### ۱) اتصال پنل اصلی

**🛰 پنل‌های اصلی ← ➕ اتصال پنل جدید** و این‌ها را بدهید:

| مورد | توضیح |
|------|-------|
| نام | فقط برای نمایش؛ در ربات مشتری هم به همین نام اضافه می‌شود |
| آدرس | مثل `https://panel.example.com` |
| روش ورود | **API Key** (پیشنهادی) یا نام کاربری/رمز یک ادمین sudo |

پیام حاوی رمز یا API Key پس از دریافت **پاک می‌شود** و رمزنگاری‌شده ذخیره می‌شود. ربات‌ساز بلافاصله اتصال را تست می‌کند.

</Step>
<Step>

### ۲) انتخاب نقش و گروه‌ها

- **🎭 نقش:** نقشی که ادمین‌های مشتری روی پنل می‌گیرند. محدودیت‌های دسترسی از همین نقش می‌آید؛ نقش را طوری بسازید که فقط کاربر بسازد و ادمین دیگر را نبیند.
- **👥 گروه‌ها:** گروه‌هایی که ربات مشتری برای کاربرانش استفاده می‌کند. اگر هیچ‌کدام انتخاب نشود، همهٔ گروه‌های پنل.

تا نقش انتخاب نشود، فروش آن پنل ممکن نیست.

</Step>
<Step>

### ۳) تعریف پلن‌ها

**📦 پلن‌های پنل ← ➕ پلن جدید:** پنل اصلی را انتخاب کنید و نوع را بگویید:

| نوع | فیلدها |
|------|--------|
| 📅 **پلن ماهانه** | نام، حجم (GB)، مدت (روز)، سقف تعداد کاربر ادمین، قیمت (تومان) |
| ➕ **بستهٔ حجم اضافه** | نام، حجم (GB)، قیمت |

هر پلن روی یک پنل اصلی فروخته می‌شود. پلنِ پنلِ غیرفعال به مشتری نشان داده نمی‌شود.

</Step>
</Steps>

بعدش دکمهٔ **🧩 پنل‌ها** در منوی ربات‌ساز برای مشتری‌ها ظاهر می‌شود (از **⚙️ تنظیمات ← 🧩 فروش پنل** قابل خاموش کردن است).

## تجربهٔ مشتری

| مرحله | توضیح |
|--------|-------|
| 🧩 پنل‌ها ← ➕ خرید پنل جدید | انتخاب پلن (باید حداقل یک ربات داشته باشد؛ اگر چند ربات دارد انتخاب می‌کند پنل به کدام وصل شود) |
| پرداخت | کیف پول (فوری) یا کارت‌به‌کارت (بعد از تأیید رسید)، کد تخفیف هم کار می‌کند |
| تحویل | ادمین ساخته می‌شود و ربات وصل می‌شود؛ آدرس، نام کاربری و رمز در پیام می‌آید |
| 📊 جزئیات پنل | مصرف با نوار پیشرفت، اعتبار، وضعیت اتصال ربات |
| 🔄 تمدید | یک دورهٔ تازه: **مصرف صفر می‌شود**، حجم تازه و مدت جدید (روی باقی‌ماندهٔ اعتبار جمع می‌شود) |
| ➕ حجم اضافه | بسته‌های حجم؛ اگر حجم تمام شده بود، پنل دوباره فعال می‌شود |
| 🔑 اطلاعات ورود / 🔐 تغییر رمز | رمز جدید می‌سازد و ربات مشتری خودکار به‌روز می‌شود |

اگر مشتری پنل را پیش از آماده شدن رباتش بخرد (مثلاً هنوز توکن نفرستاده)، پنل ساخته می‌شود و **به‌محض بالا آمدن ربات** خودکار وصل می‌شود.

## نظارت خودکار

هر ۵ دقیقه ربات‌ساز مصرف همهٔ پنل‌های فعال را از پنل اصلی می‌خواند:

| رویداد | کار |
|---------|-----|
| مصرف به ٪ تنظیم‌شده رسید (پیش‌فرض ۸۰٪) | یک‌بار هشدار برای مشتری |
| حجم تمام شد | ادمین روی پنل **غیرفعال** و ربات مشتری هم غیرفعال می‌شود؛ پیام با دکمهٔ «حجم اضافه / تمدید» |
| چند روز تا پایان مدت (پیش‌فرض ۳ روز) | یک‌بار یادآوری تمدید |
| مدت تمام شد | غیرفعال‌سازی و پیام تمدید |
| ربات هنوز وصل نیست | تلاش دوبارهٔ اتصال |
| ادمین روی پنل اصلی حذف شده | وضعیت «خطا» و هشدار |

ادمین مشتری **هیچ‌وقت خودکار حذف نمی‌شود** (حذف ادمین یعنی حذف همهٔ کاربرانش)؛ فقط غیرفعال می‌شود. حذف فقط به‌دست شما انجام می‌شود.

## مدیریت پنل‌های فروخته‌شده

**🧩 فروش پنل ← 🧩 پنل‌های فروخته‌شده** هر پنل را با مصرف زنده نشان می‌دهد و این امکانات را دارد:

| دکمه | کار |
|------|-----|
| ⏸ / ▶️ | غیرفعال یا فعال کردن (روی پنل و ربات مشتری) |
| ➕ روز / ➕ حجم | افزودن بدون پرداخت |
| 🔐 ریست رمز | رمز جدید می‌سازد و برای مشتری می‌فرستد |
| 🔗 اتصال مجدد | دوباره ربات مشتری را وصل می‌کند |
| 🔑 اطلاعات ورود | نمایش آدرس/نام کاربری/رمز |
| 🔁 تلاش مجدد ساخت | اگر بعد از پرداخت ساخت روی پنل خطا داد (پول مشتری ثبت‌شده می‌ماند) |
| 🗑 حذف | ادمین را با همهٔ کاربرانش از پنل اصلی و پنل را از ربات مشتری برمی‌دارد |

اگر ساخت ادمین بعد از پرداخت خطا بدهد، مشتری پیام «در حال بررسی» می‌گیرد، متن خطا برای ادمین‌های ربات‌ساز می‌آید و با «🔁 تلاش مجدد» همان نام کاربری و رمز دوباره استفاده می‌شود (حتی اگر پنل ادمین را ساخته ولی جوابش را نداده باشد، همان را برمی‌دارد و دوبار نمی‌سازد).

## امنیت

- رمز/API Key پنل اصلی و رمز ادمین مشتری‌ها با `BUILDER_SECRET_KEY` رمزنگاری می‌شوند.
- اتصال ربات مشتری از طریق `docker exec` است و رمز از **stdin** می‌رود، نه از خط فرمان (در `ps` دیده نمی‌شود).
- ادمین مشتری فقط همان نقشی را دارد که شما انتخاب کرده‌اید؛ نقش را با کمترین دسترسی لازم بسازید.
- هر مشتری فقط پنل‌های خودش را می‌بیند و دستکاری می‌کند (همهٔ دکمه‌ها مالکیت را بررسی می‌کنند).

## عیب‌یابی

| مشکل | راه‌حل |
|-------|---------|
| «unauthorized» هنگام اتصال | API Key / رمز را بررسی کنید؛ نقش اکانت باید اجازهٔ ساخت ادمین داشته باشد |
| پلن‌ها به مشتری نشان داده نمی‌شود | پنل اصلی فعال و **نقش انتخاب‌شده** و پلن فعال باشد |
| ساخت ادمین «422» می‌دهد | سیاست رمز یا محدودیت‌های نقش پنل؛ متن خطا را در پیام ادمین ببینید |
| ربات مشتری وصل نمی‌شود | ربات باید در حال اجرا باشد؛ «🔗 اتصال مجدد» را بزنید یا لاگ ربات را ببینید |

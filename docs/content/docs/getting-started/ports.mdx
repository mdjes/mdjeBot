نصب ربات‌ساز سه پورت ثابت و یک بازهٔ پورت را روی سرور می‌گیرد. اسکریپت نصب قبل از شروع آزاد بودن پورت‌های ثابت را چک می‌کند.

| پورت | سرویس | گوش می‌دهد روی | از اینترنت در دسترس؟ |
|------|-------|----------------|----------------------|
| `6161` | Redis | فقط `127.0.0.1` | خیر |
| `6162` | MariaDB | فقط `127.0.0.1` | خیر |
| `6163` | phpMyAdmin | همهٔ اینترفیس‌ها | **بله**، بهتر است محدودش کنید |
| `7000`–`7999` | ربات‌های مشتری (هر کدام یک پورت) | همهٔ اینترفیس‌ها | فقط اگر مشتری وب‌هوک/وب‌اپ لازم داشته باشد |

ربات‌ساز خودش پورت عمومی ندارد؛ فقط به تلگرام وصل می‌شود. Redis و MariaDB فقط روی localhost باز هستند و کانتینرها از طریق شبکهٔ داخلی Docker به هم وصل می‌شوند (`redis:6379` و `mariadb:3306`).

## پورت ربات‌های مشتری [#tenants]

هر ربات مشتری یک وب‌سرور داخلی (FastAPI) روی پورت `6160` **داخل کانتینر** خودش دارد که روی یک پورت از بازهٔ `7000`–`7999` سرور منتشر می‌شود. این پورت برای وب‌هوک پنل پاسارگارد، وب‌اپ و پرداخت‌هایی مثل TonPays لازم است. اگر مشتری هیچ‌کدام را استفاده نکند، می‌توانید پورتش را در فایروال بسته نگه دارید؛ خود ربات تلگرام بدون آن هم کار می‌کند.

شمارهٔ پورت هر ربات در پنل ادمین ربات‌ساز (جزئیات ربات) و برای مشتری در «ربات‌های من» (وقتی «دامنه/IP سرور» تنظیم شده باشد) نمایش داده می‌شود. بازه را با `BUILDER_PORT_START` و `BUILDER_PORT_END` در `.env` عوض کنید.

<Callout type="info">
پورت‌های `6161`، `6162` و `6163` در فایل docker-compose ثابت هستند. تغییرشان با **`6) Edit docker-compose.yml`** ممکن است، ولی آپدیت بعدی فایل را دوباره از گیت‌هاب می‌گیرد و تغییر شما از بین می‌رود.
</Callout>

## پورت اشغال است [#busy]

اگر هنگام نصب ببینید:

```text
[!] Port 6160 appears to be in use.
Continue anyway? (y/N):
```

یعنی برنامهٔ دیگری روی آن پورت است. پیدا کردنش:

```bash
ss -ltnp | grep -E ':(6160|6161|6162|6163)\s'
```

آن برنامه را متوقف کنید یا (برای 6160) پورت ربات را عوض کنید. اگر با `y` ادامه دهید، کانتینری که پورتش اشغال است بالا نمی‌آید.

## فایروال [#firewall]

حداقل‌های لازم:

| پورت | پیشنهاد |
|------|---------|
| `22` (SSH) | باز (یا هر پورتی که SSH روی آن است) |
| `6160` | باز (برای پنل پاسارگارد، تلگرام و کاربران وب‌اپ) |
| `80` | فقط هنگام گرفتن/تمدید SSL با AutoSSL باید باز باشد |
| `6163` | **فقط برای آی‌پی خودتان** یا بسته |

نمونه با `ufw`:

```bash
ufw allow 22/tcp
ufw allow 6160/tcp
ufw allow 80/tcp
ufw enable
```

<Callout type="warn" title="Docker قوانین ufw را دور می‌زند">
پورت‌هایی که Docker منتشر می‌کند (`6160` و `6163`) مستقیم در iptables باز می‌شوند و **`ufw deny 6163` جلویشان را نمی‌گیرد**. برای محدود کردن phpMyAdmin از زنجیرهٔ `DOCKER-USER` استفاده کنید:

```bash
# فقط آی‌پی 203.0.113.10 به phpMyAdmin دسترسی داشته باشد
iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 6163 ! -s 203.0.113.10 -j DROP
```

این قانون با ریبوت پاک می‌شود؛ برای ماندگاری از `iptables-persistent` (`netfilter-persistent save`) استفاده کنید.
</Callout>

راه ساده‌تر برای phpMyAdmin: بستن کامل 6163 با قانون بالا (بدون آی‌پی مجاز) و دسترسی از طریق تونل SSH:

```bash
ssh -L 6163:127.0.0.1:6163 root@SERVER_IP
# سپس در مرورگر خودتان: http://127.0.0.1:6163
```
